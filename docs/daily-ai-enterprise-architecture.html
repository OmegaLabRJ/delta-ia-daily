Executive Architecture

Understand the entire system in under 2 minutes. The Daily platform is a Dual-AI commerce engine serving both merchants (B2B) and consumers (B2C) through a single, unified application.

The Core Insight: Daily is not a chatbot with features. It is an AI Operating System where every business operation — scheduling, pricing, marketing, CRM, finance — is executed by specialized AI agents through natural language. Zero prompt engineering required from the user.

Section 02

AI Architecture

The intelligence layer is architected as a Dual-Persona Agentic System where a central Router orchestrates domain-specific specialists, each with isolated context, tools, and memory.

Dual Persona Model

🏪 Consultora Daily (B2B)

The AI Business Partner for merchants and professionals. Handles 8 specialized domains: scheduling, pricing, marketing, analytics, CRM, finance, onboarding, and strategy. Accessed from the professional profile tab.

🛒 Delta do Daily (B2C)

The AI Shopping Assistant for consumers. Provides frictionless product/service discovery, real-time availability checking, and one-tap booking directly from the chat interface. Uses local keyword parsing for zero-latency intent detection.

Router Intelligence — 3-Layer Classification

The Router (router.ts) classifies user intent across 8 domains using a progressive confidence-based pipeline. Each layer only fires if the previous layer's confidence is insufficient.

LAYER 1: Local Regex Classifier (0 tokens, 0 latency) │ ├── Confidence ≥ 0.8 ──→ Dispatch directly to Agent │ ├── Extra Pattern Matching (CRM, Finance, Agenda deep patterns) │ ├── Session Continuity Check (short replies: "sim", "ok", "pode") │ └── Onboarding Override (new professionals → force onboarding) LAYER 2: Gemini Flash Micro (~10 tokens, temperature: 0.1) │ ├── Fires when local confidence is 0.4–0.8 │ └── Uses ROUTER_PROMPT + session context + last 5 exchanges LAYER 3: Gemini Full (with conversation history) │ ├── Fires when confidence < 0.4 │ └── Full contextual history analysis FALLBACK └── Strategy Agent (or Onboarding if new user)

Agent Isolation Pattern

Each agent operates in a fully sandboxed environment with its own system prompt, context builder, and tool set. This ensures zero cross-contamination and minimizes token consumption.

Each Specialist Agent = { type: AgentType // "agenda" | "pricing" | ... prompt: prompts/{agent}.prompt.ts // Persona-tuned system prompt contextBuilder: contexts/{agent}.context.ts // SQL data fetcher (isolated queries) tools: tools/{agent}.tools.ts // Domain-specific function declarations executor: base.agent.ts // Shared execution with tool call loop }

Section 05

Security Architecture

Defense-in-depth security ensuring zero data leakage between tenants, API key protection, and full auditability of all AI operations.

SECURITY LAYERS — DEFENSE IN DEPTH React Native App │ ▼ ┌──────────────────┐ │ Supabase Auth │ ← JWT Token Verification │ (GoTrue) │ Every request authenticated └────────┬─────────┘ ▼ ┌──────────────────┐ │ HTTPS/TLS │ ← Encrypted in transit │ (All traffic) │ No plain HTTP allowed └────────┬─────────┘ ▼ ┌──────────────────┐ │ Edge Functions │ ← API Keys stored server-side ONLY │ (Deno Runtime) │ Client never sees Gemini API key │ │ Atomic RPC for usage tracking └────────┬─────────┘ ▼ ┌──────────────────┐ │ Gemini API │ ← Server-to-server only │ (Google Cloud) │ Rate-limited + usage-tracked └────────┬─────────┘ ▼ ┌──────────────────┐ │ PostgreSQL │ ← Row Level Security (RLS) active │ (Supabase) │ on ALL tables └────────┬─────────┘ ▼ ┌──────────────────┐ │ Audit Layer │ ← ai_usage_logs + ai_action_feedbacks │ (Observability) │ Latency, status, user_id per call └──────────────────┘

Security Controls

JWT Authentication

Every request carries a Supabase JWT. Edge Functions validate the token before any LLM call. Expired or missing tokens are rejected at the gateway.

Row Level Security (RLS)

Enforced at the PostgreSQL level on ALL tables. Users can only read/write their own data. Context builders filter by seller_id / professional_id. Zero cross-tenant leakage.

API Key Isolation

Gemini API keys are stored as Supabase Edge Function secrets. The React Native client never accesses them directly. All LLM traffic routes through gemini-chat Edge Function.

Atomic RPC — Race Condition Prevention

Usage counters use increment_ai_usage() Postgres RPC with ON CONFLICT ... DO UPDATE to prevent double-counting under concurrent load. SECURITY DEFINER ensures isolation.

Tool Validation

Each agent can only invoke its own declared tool set. The BaseAgent executor enforces tool-set boundaries. An Agenda Agent cannot call pricing tools.

Audit Trail

ai_usage_logs records every AI call with user_id, action_type, latency_ms, and status. ai_action_feedbacks tracks user reactions (accepted/edited/cancelled) for quality telemetry.

Competitive Differentiators

vs. Generic Chatbot SaaS

Not a wrapper around GPT. Purpose-built 8-agent architecture with domain isolation, function calling, and real database mutations. Each agent has its own prompt, context, tools, and memory scope.

vs. Multi-Tenant Platforms

Single-tenant by design. Each client gets a dedicated database, dedicated AI brain, and 100% data isolation. No risk of cross-tenant data leakage.

vs. Vertical SaaS (No AI)

Existing vertical SaaS platforms (Fresha, Booksy) don't have agentic AI. Daily offers the same operational features PLUS a full AI business partner that autonomously manages marketing, pricing, and strategy.

vs. AI Wrappers

3-layer classification saves 73% of API calls. Atomic RPCs prevent race conditions. Edge Functions keep API keys server-side. This is production engineering, not a demo.
